## 1. 任务理解与三条关键判断

### 1.1 一句话目标

在普通前置摄像头 + 极度受限的端侧算力下，构建开箱即用的轻量端侧视线估计模型，并通过无感自适应校准闭环，把未校准误差从 ≤1.5 cm 进一步降到「日常使用 1 周后 ≤1.0 cm」，最终通过 3 人以上真人全场景盲测验收。

同时，以 **「隔空画画」现场 Demo** 作为对外交付形态：手势当画笔（握拳落笔 / 张开抬笔）、眼动选颜色，让观众当场画一幅作品送给评委，用真实观众场景验证可用性。

### 1.2 最终交付物

1. 轻量端侧模型（参数量 < 5M、计算量 < 1G FLOPs、输入 ≤ 1024×768 灰度）
2. 无感自适应校准闭环（不弹窗、隐式进行）
3. GazeSDK（统一输出：注视点 + 置信度 + 事件）
4. 3 人以上真人全场景盲测报告
5. **现场交付 Demo：隔空画画**——握拳落笔 / 张开抬笔，眼动选色，观众可当场作画并「画一幅送给评委」（详见第 9 节）

### 1.3 三个攻坚点

| 序号 | 攻坚点 | 风险等级 |
|---|---|---|
| ① | 未校准平均误差 ≤ 1.5 cm 这一硬指标 | 高 |
| ② | 头部姿态与视线解耦（大角度转头场景） | 中 |
| ③ | 在线微调导致的性能漂移控制 | 高 |

### 1.4 关键判断

- **判断一**：整条链路的成败押在「阶段 4 的未校准精度」上，其余模块都是它的支撑。排期上必须让 P1 + P2 从第 1 周就并行跑基线，不能等端侧做完再谈精度。
- **判断二**：评测口径必须在写第一行训练代码前冻结，否则后期所有误差数字不可比。
- **判断三**：数据采集 App（帧 + 真值 + 触控事件）是关键路径上的阻塞项，先做出来才能解锁后面 6 个阶段。

## 2. 开工前必须冻结的 8 个决策门

其中 1–5 对应系统设计报告 1.5 节待确认项，6–8 由「隔空画画」现场交付形态引入。建议第 1 周内闭环，未否决即按下列默认值执行。

| # | 决策门 | 建议默认值 | 决策人 |
|---|---|---|---|
| 1 | 帧率 / 延迟口径 | 主口径「单帧端到端 ≤ 30 ms」，副口径「≥ 30 FPS」，二者等价，避免验收争议 | P4 主持 |
| 2 | 误差换算口径 | 锁定 3 台基准机型（高/中/低端各一），明确屏幕物理尺寸与 DPI 换算公式；误差以 cm 报告并附像素值 | P2 |
| 3 | 输入定义 | 全帧灰度化 ≤ 1024×768 为采集上限，实际送入模型的是眼部 ROI（更小）；1024×768 非模型输入 | P1 |
| 4 | 触控样本合法性 | 仅「单点点击」计入校准样本，滑动/长按/多指一律排除；默认「点击瞬间注视点 ≈ 点击中心」，允许 ± 容差 | P4 |
| 5 | 隐私与数据边界 | 自采数据仅存 ROI 特征与伪标签；原始人脸帧用后即弃、不出设备、不入库 | P4 |
| 6–8 | 隔空画画 Demo 相关 | 摄像头策略、选色触发方式、手眼时序关系 —— 详见第 9.3 节 | P4 主持 |

**出口标准**：形成一份《需求与口径冻结单》，全员签字确认后，后续任何口径变更走评审流程。

## 3. 四人分工（核心）

按「一人一块、边界不重叠、各自有独立可验收产物」原则划分。

### 3.1 分工总表

| 代号 | 角色 | 主责模块 | 核心交付物 | 兼责 |
|---|---|---|---|---|
| **P1** | 算法负责人（模型与解耦） | M3 头部姿态、M4 眼部归一化、**M5 视线估计**、**M6 映射与解耦** | 归一化空间视线模型；head-pose / gaze 双分支结构；混合损失（角度 + 屏幕误差）；蒸馏 + 剪枝 + INT8 量化产物；解耦消融报告 | 模型版本与四项指标记录 |
| **P2** | 数据与评测负责人 | M2 检测组件选型验证、**M11 评测与盲测** | 采集数据规格与标注规范；公开数据集接入（ETH-XGaze / Gaze360 / MPIIFaceGaze / EVE / UT-Multiview）；自采手机数据集；统一评测脚本（均值 / 70% / 90% 分位）；基线复现报告；盲测方案与报告 | 指标看板维护 |
| **P3** | 端侧与客户端工程负责人 | M1 帧采集与预处理、推理引擎、**M10 SDK 封装** | CameraX / AVFoundation 灰度帧管线；ONNX Runtime / TFLite 接入与算子冒烟；Flutter 业务层 + 原生算法插件（MethodChannel）；帧率 / 功耗优化；机型分级适配 | 仓库骨架、CI、打包发版 |
| **P4** | 校准闭环与系统负责人 | **M7 高置信筛选**、**M8 在线微调**、**M9 防漂移** | 触控伪标签筛选器（误纳率 / 漏纳率达标）；冻结特征 + 可训练适配层的端侧微调；校验集回放与回滚机制 | 项目管理、接口契约、隐私合规、集成联调 |

### 3.2 边界约定（防止职责撕扯）

- 采集 App 的**实现**归 P3，采集的**数据规格与标注规范**归 P2。
- 人脸检测与关键点（M2）**不自研**：P2 负责选型验证，P3 负责集成，P1 只消费其输出。
- 模型导出格式与推理引擎接口契约由 **P1 与 P3 共同签署**，P4 归档。
- 屏幕几何标定工具归 P3 实现，标定精度验收归 P2。
- 在线微调只更新「个人校准 / 映射层」，共享特征层冻结 —— 此约束由 P1 定义、P4 执行。

## 4. 八阶段分工矩阵

| 阶段 | 目标 | P1 算法 | P2 数据评测 | P3 端侧工程 | P4 校准系统 |
|---|---|---|---|---|---|
| **0** 需求与准备 | 冻结需求与基准 | 定义精度与指标计算 | 数据规格 + 标注规范 | 采集 App MVP + 仓库 / CI | 主持对齐 + 合规初判 + 看板 |
| **1** 数据与基线 | 建立评测闭环 | 骨干选型调研 | 数据集整合 + 评测脚本 + 基线复现 | 数据落盘 / 命名 / 版本 | 口径固化 + 进度管控 |
| **2** 轻量模型 | 达 < 5M / < 1G | 训练 + 蒸馏 + 剪枝 + INT8 | 验证集评测 | 端侧 30 FPS 冒烟 | 四项指标入看板 |
| **3** 头部解耦 | 姿态 / 视线解耦 | 归一化空间 + 双分支 + 消融 | 大角度专项评测集 | 双分支端侧时延 | 解耦评审门禁 |
| **4** 注视点映射 | 厘米级落点 | 映射层 + 混合损失 | 多机型 / 多视距抽测 | 屏幕几何 / 内参标定工具 | **≤ 1.5 cm 门禁裁决** |

## 6. 协作与工程规范

### 6.1 仓库结构（建议）

```
app/      Flutter 业务层
sdk/      原生算法插件（iOS / Android）
algo/     模型训练与导出
data/     数据清单与工具（数据本体不入库）
eval/     评测脚本 + 固定评测集清单
docs/     设计与流程文档
```

### 6.2 流程纪律

- **分支**：`main` + `dev` + `feat-*`；任何合并至少 1 人 review。
- **双签机制**：模型结构变更、评测口径变更需 P1 + P2 双签。
- **版本与可复现**：每次训练产出 manifest（参数量 / FLOPs / 时延 / 精度）；数据集以清单哈希固化版本。
- **CI**：评测脚本自动跑 + 多推理引擎算子冒烟。
- **例会**：每日 15 分钟站会（阻塞项优先）；每周一次 45 分钟进度与指标评审，由 P4 主持。
- **口径纪律**：固定评测集与误差口径不得私自更改。

## 9. 现场交付形态：隔空画画 Demo 专项

### 9.1 交付定义

观众 / 评委无需穿戴任何设备，隔空完成一幅画：

| 交互 | 手段 | 判定 |
|---|---|---|
| 落笔 | 握拳 | 手部状态二分类 + 滞回防抖 |
| 抬笔 | 张开手掌 | 同上 |
| 选色 | 眼睛注视颜色面板 | 注视停留（dwell）触发 |
| 产出 | 画布导出 PNG / 扫码取图 | 客户端功能 |

- 单次体验时长目标 **30–60 秒**，支持「画一幅送给评委」。
- 体验者零学习成本：现场需有 10 秒内的引导动画或语音提示。

### 9.2 新增模块（在原 M1–M11 之外）

| 模块 | 名称 | 说明 | 主责 |
|---|---|---|---|
| M12 | 手部状态识别 | 手部关键点 / 区域检测 + 握拳·张开二分类，端侧实时，含滞回与防抖 | P3 |
| M13 | 画笔渲染引擎 | 轨迹平滑、笔宽与透明度、撤销、清空、导出 PNG / 二维码分享 | P3 |
| M14 | 眼动选色交互 | 调色板 UI + dwell 停留触发 + 进度环反馈 + 误触抑制 | P4 |
| M15 | 演示编排与现场运维 | 彩排脚本、兜底方案、灯光背景适配、设备看管 | P4 |

### 9.3 必须先拍板的三个技术决策

| # | 决策 | 推荐方案 | 理由 |
|---|---|---|---|
| 6 | 摄像头策略 | 单一前置摄像头，画面内「远端脸 + 近端手」分层处理 | 前置是唯一稳定朝向用户的相机；后置需他人持机，破坏「隔空」体验 |
| 7 | 选色触发方式 | 注视 + dwell 600–900 ms + 进度环 | 单纯注视点无法区分「看」与「选」，必然误触 |
| 8 | 手眼时序关系 | 分时复用：选色时手放低，绘制时专注手势 | 手抬到镜头前会遮挡面部，导致眼动信号丢失 |

### 9.4 Demo 专项分工

| 成员 | Demo 主责 | 具体交付 |
|---|---|---|
| P1 | 手眼时序仲裁 | 手势状态稳定化滤波（滞回 / 中值 / 迟滞阈值）；手遮挡时的眼动降级策略；共享骨干或分时调度的算力方案 |
| P2 | 可用性评测 | 真人试用测试：落笔 / 抬笔误判率、选色成功率、平均完成时长；现场光照与背景条件的数据增补 |
| P3 | 摄像头与渲染 | M12 手部状态端侧实现；M13 画笔渲染引擎；双 ROI（脸 / 手）采集管线；现场设备适配 |
| P4 | 选色交互与编排 | M14 dwell 选色交互；M15 演示编排、彩排、兜底方案与现场运维 |

### 9.5 Demo 新增风险

| 风险 | 责任人 | 应对 |
|---|---|---|
| 手遮挡面部导致眼动丢失 | P1 | 遮挡检测 + 画笔冻结 + 提示「移开手」 |
| 手势 / 眼动双网络超算力预算 | P1 | 分时调度或共享骨干，实测端到端时延 |
| 现场光照 / 背景与实验室差异 | P2 | 采集阶段补现场条件数据；演示现场预跑 |
| 观众手势五花八门误触发 | P1 / P3 | 收敛支持的手势集，展示前做手势引导 |
| 现场演示翻车 | P4 | 至少 3 次全流程彩排 + 录屏兜底 |

### 9.6 排期插入点

| 时点 | 事件 |
|---|---|
| W8 | 手势画笔单机可玩（不依赖眼动），先验证交互手感 |
| W12 | 手势 + 眼动打通，内部可演版本（与 M1 里程碑同步） |
| W15 | Demo 功能冻结，进入彩排 |
| W16 | 全流程彩排 ≥ 3 次，随盲测一并验收 |

> **重要提示**：Demo 不能等到 W15 才动手。M12（手势）从阶段 2 起就应与主线并行，否则会撞上阶段 6、7 的联调高峰。

## 10. 附：验收指标红线（全员对齐）

| 维度 | 指标 | 阈值 |
|---|---|---|
| 模型规模 | 参数量 | < 5M |
| 计算量 | FLOPs（单帧推理） | < 1G |
| 输入 | 分辨率 / 类型 | ≤ 1024×768 灰度 |
| 视距 | 有效工作距离 | 25–60 cm |
| 精度 | 未校准平均误差 | ≤ 1.5 cm |
| 精度 | 未校准分位 | 70% ≤ 1.5 cm，90% ≤ 2 cm |
| 精度 | 使用 1 周后平均误差 | ≤ 1.0 cm |
| 性能 | 单帧端到端时延 / 帧率 | ≤ 30 ms 或 ≥ 30 FPS |
| 质量 | 盲测 | 3 人以上全场景通过 |
| 隐私 | 原始人脸数据 | 端侧处理，不出设备 |
| **Demo** | 落笔 / 抬笔误判率 | ≤ 5% |
| **Demo** | 选色成功率（首次注视即中） | ≥ 90% |
| **Demo** | 单幅作品完成时长 | 30–60 s |
| **Demo** | 零引导上手 | 无需讲解，10 s 内理解玩法 |
