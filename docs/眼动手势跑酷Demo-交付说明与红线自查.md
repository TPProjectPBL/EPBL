## 二、本地运行

摄像头受 `getUserMedia` 限制，**必须**在 `localhost` 或 HTTPS 下打开：

```bash
cd EPBL && python3 -m http.server 8777 --bind 127.0.0.1
# 双模态体验（默认）
open http://127.0.0.1:8777/eye-page-turner/demo/air-runner/
```

| 参数 | 作用 |
| --- | --- |
| （无） | 首屏（含 4 条手势图解速查）→ 点「开始游戏」申请摄像头，默认**双模态**（眼动变道 + 手势跳跃/滑铲/护盾） |
| `?mode=dual` | 显式双模态（默认值） |
| `?mode=gaze` | **纯眼动**：只保留三区变道，不喂手势；坐姿远、手不想动时用 |
| `?mode=hand` | **纯手势**：竖直挥=跳/滑铲，左右挥=变道；眼动不参与 |
| `?mode=mouse` | 鼠标 + 键盘兜底（← → ↑ ↓ 空格 F） |
| `?mode=sim` | **自动演示**：合成 21 点手部关键点走真实识别链路，**不申请摄像头**，可无设备直接预览 |
| `?nocam=1` | 禁止启动摄像头（强制鼠标兜底） |
| `?skipintro=1` | 教学门直接判定完成（跳过 4 项练习，不是跳过首屏） |
| `?autostart=1` | 跳过全部前置流程直接进游戏（展台 kiosk 用；sim 下走双模态链路并继续自动演示） |
| `?gaze=abs` | 启动时启用**绝对注视点**（需已有标定数据；没有数据会提示并自动关闭） |
| `?gazecal=1` | 开机直接进**9 点标定**屏（约 20 秒）；配 `?mode=sim` 可无摄像头看完整标定流程 |
| `?smooth=kalman` / `?smooth=oneeuro` | 光标平滑器：默认**卡尔曼**（见 §六）；`oneeuro` 切回原来的 1€ 滤波器，用于现场对比或回退 |

## 四、玩法与映射（对照设计报告）

| 能力 | 实现 |
| --- | --- |
| 眼动 = 离散三区变道 | 视口横向切三条注视带（`GazeZoneSelector`）。报告里眼动最擅长的就是离散区域选择：跑酷变道只有 3 个状态、误差容忍度极高，且天然规避「所有注视都变成动作」的抖动 —— 只有跨区才产生动作 |
| 注视 dwell 触发 | 停在某区 `gazeMs` 后变道；默认 350ms，可在设置里切 200（快）/ 350（标准）/ 500（稳）；跨区立即重置累积，220ms 冷却防连发 |
| 手势 = 竖直挥跳/滑铲 | 向上挥 = 跳跃（660Hz 提示音 + JUMP 闪字）、向下挥 = 滑铲（SLIDE） |
| 手势 = 左右挥变道（仅 `hand` 模式） | `SwipeLaneDetector` 阈值 1.0 倍掌宽，比竖直方向更保守（避免 "手一挪就换道"） |
| 握拳 = 护盾 | 复用 M12 握拳分类 + 3 帧防抖；护盾 2600ms、冷却 8000ms，HUD 显示就绪状态 |
| `gaze` 模式不喂手势 | 手扶脸 / 挠头 / 拿杯子都不会被判成跳跃指令（`wantWipe` 门控） |
| 游戏内不看 HUD | 视线落在顶部 HUD 区域（`y < 0.16`）时不分发变道，避免「看暂停钮顺手变道」 |
| 分时复用（报告决策 8） | 前置 UI 全部按钮支持注视 dwell 点击（800ms + 进度环），游戏中眼动只做变道 —— 同一模态在不同阶段承担不同粒度 |
| UI 不直接引用 MediaPipe | UI 层只消费归一化坐标与事件；模型对象仅存在于 `app.js` 采集层 |

游戏规则：3 条车道 / 3 条命 / 默认 60 秒；`block` 护栏（跳跃或变道避开）、`low` 低矮障碍（必须跳）、`high` 高处障碍（必须滑铲或变道）；撞击后 1200ms 无敌闪烁；难度系数 休闲 0.78 / 标准 1 / 硬核 1.35（影响生成间隔与障碍类型分布）；最高分存 `localStorage('air-runner.best')`；结算可导出战绩卡 PNG。

## 五、手势挥动的抗误触发设计（本次重点重构）

原设计是「冻结锚点 + 累积位移」：记下发招时刻的手位当锚点，之后累计位移超过阈值就发招。现场推演发现两个硬伤：

1. **回手被当成反向挥动** —— 向上挥完把手放下，位移方向朝下，会被判成滑铲（跳跃完立刻滑铲，操作感崩坏）；
2. **缓慢漂移误触发** —— 手慢慢下移两个掌宽（坐姿调整、拿水杯）也能凑够累积位移。

改为 **滑动窗口位移 + 重新武装**，四条抗误触同时生效：

| # | 机制 | 作用 |
| --- | --- | --- |
| 1 | 只统计最近 `window = 280ms` 的位移（按掌宽归一化） | 「挥动」变成一个短时间窗内的动作，缓慢漂移再远也不触发 |
| 2 | 位移做 EMA 平滑（`smoothing = 0.55`） | 压关键点抖动，静止时不会累积出假位移 |
| 3 | 发招后进入 **未武装** 状态，必须「窗口内位移 < `settleRatio(0.4)` 持续 `settleMs(110)` 毫秒」才重新武装 | 回手动作本身不产生新指令；手必须先停稳才能出下一招 |
| 4 | 触发后 480ms 冷却 + 手消失超过 `window*2` 时重建参考 | 防连发；手离开画面再回来不会因为「位移跳变」误发 |

阈值：竖直 0.85 掌宽（`WipeDetector`）、水平 1.0 掌宽（`SwipeLaneDetector`）。竖直更容易触发（跳跃/滑铲是高频动作），水平更保守（变道做错代价大）。灵敏度设置低/中/高按比例缩放阈值。

自测覆盖了这些边界：向上挥触发跳跃、向上挥后**回手不触发滑铲**、停稳后可再次触发、缓慢下移 2 个掌宽不触发、静止抖动不触发、手远离画面（关键点整体缩小）不误触发、手消失重现不误触发。

## 六、9 点精确注视标定（本轮新增，demo 级绝对注视点）

> 目的：报告阶段 3「眼神方向估计」尚未交付，原来的注视点只是虹膜相对偏移的代理（粗、且头一动就漂）。
> 这一版把「个人 9 点标定」做通：**用 20 秒的标定，把相对偏移标定成屏幕绝对坐标**，让三区变道之外还能做「注视任意按钮」。

### 流程（每点约 1.55 秒，共 9 点约 20 秒）

1. 进入标定屏，9 个目标点画在**画布的 10%/50%/90% × 12%/50%/88%** 位置（渲染时按元素真实矩形换算成屏幕坐标，避免"点和目标对不上"）；
2. 当前点放大呼吸 + 进度环；前 **350ms 只等眼球转到位，不采样**；随后 **1200ms 采帧**（约 30–45 帧；帧越多，中位数越稳、离群剔除越有效）；
3. 每点：逐帧算特征 → **MAD 剔除离群帧**（眨眼残留、检测跳变；最多丢一半，避免误杀）→ 逐坐标取中位数关键点 → 再由中位数关键点算特征（顺序很关键，见 §八缺陷 9）；
4. **两套候选特征集各自拟合**（含头动项 / 不含头动项，见下），各做**留一交叉验证**，取误差小的那套；
5. 按平均留一误差评级：≤5% 优 / ≤9% 良 / 更高偏低；
6. **退化门**（本轮新增）：眼球信号强度不足（横向 <0.012 或纵向 <0.008 眼宽）或平均误差 >25% → **判定本次标定不可用**，「应用并返回」保持禁用，绝不把乱飞的光标交给用户；
7. 结果屏给出：**误差图**（圆点=目标，小叉=模型预测落点）+ **多行中文诊断**（能不能用 / 为什么 / 怎么做）+「复制诊断数据」按钮（导出结构化 JSON，便于把真实数据带回开发者排查）；
8. 「应用并返回」→ 写 `localStorage`（`air-runner.gazeModel`，格式 v3）+ 自动打开精确注视；取消/重做不落盘，一次失败的重新标定**不会顶掉已生效的旧模型**。

### 特征设计（为什么不用"眼眶内比值"）

| 特征 | 含义 | 进入哪套模型 |
| --- | --- | --- |
| `dLx/dLy/dRx/dRy` | 虹膜相对眼眶中心的位移，**按眼宽归一化**（≈0.052 归一化单位，比眼眶高 0.02 大 2.6 倍，抖动被压得更小）；眼眶中心用**内外眼角的 y 中点**，比上下眼睑中点更抗眨眼/眯眼 | 两套都有 |
| `faceCx/faceCy` | 人脸中心（头平移补偿） | **仅 full 集** |
| `eyeDist` | 双眼间距（远近/尺度补偿） | 两套都有 |
| `roll` | 双眼连线倾角（头歪补偿） | 两套都有 |

**为什么头动项要"按证据决定用不用"**：头平移会让虹膜与眼眶中心一起移动，而 `(虹膜 − 眼眶中心)/眼宽` 本身对平移免疫——所以头动项**不是在补平移**，它表达的是"同一屏幕点、头位置不同时眼球需要的额外转动量"，只有**标定时头动覆盖了这些姿势**，回归才能辨识出这个系数（合成数据实测：含头动真值时 full 集留一误差 0.02%，reduced 集 5.8%）。反过来，如果用户标定时头乱动、头动又和注视目标关系不稳定，头动项就会主导拟合、把噪声当信号。两套都算一遍、用留一误差择优，是这两种情况都安全的做法；诊断里会同时给出两套分数，一眼能看出"这次是不是头动在捣乱"。

先做 z-score 标准化再解方程，`std` 有下限（0.01/0.02）防止头完全不动时除零放大噪声（**注意：下限只用于稳定分母，不再充当"信号存在"的判据——退化门用未夹取的原始标准差**，见 §八缺陷 12）。y 方向统一乘 `1/aspect`，避免 16:9 下调参不可比。

### ⚠ 真人实测六轮：50.4% → 10.2% → 6.0% → 5.2% → 6.7%（同一台机器、同一个人）

第一次在真机上跑 `?gazecal=1`，结果屏显示：

```
已标定 9 点 · 留一误差 平均 50.4% / 最大 82.9% · 评级 偏低
```

误差图特征：预测叉散布全屏、方向杂乱、**没有系统性单向偏移**（排除镜像/平移写错）。合成数据同一代码路径只有 3.6%/7%，差 14 倍。**结论：这组标定数据里「眼球位置」与「看哪里」几乎没有稳定关系。**

代码复查定位到三条根因，均已修：

| 根因 | 为什么会导致"乱飞" | 修复 |
| --- | --- | --- |
| `MIN_STD` 只用来夹分母，**从不拒绝标定** | 特征无信号时 z-score 把噪声放大成权重，输出看似合理实则随机，还标 `ok:true` | 新增 `MIN_EYE_STD` 退化门：用**未夹取**的原始标准差判定，信号不足直接判不可用 |
| 头动项（`faceCx/faceCy`）**无条件参与**建模 | 用户习惯"转头看四角"时，模型学成「头位置 → 屏幕位置」 | 改为两套特征集按留一误差自动择优（full/reduced），并在诊断里报出两套分数 |
| **没有任何质量门** | 50.4% 的废模型照旧允许「应用并返回」，光标乱飞 | `MAX_ACCEPT_ERR = 25%` 上限 + 应用按钮失败时保持禁用；`fromJSON` 也拒绝加载误差超限的历史模型（含 v2 旧格式） |

同时补上**观测手段**（本次排查最缺的东西）：每点采帧数/抖动/头部极差/离群帧数上报进 `diag`，结果页给多行中文诊断，「复制诊断数据」一键导出结构化 JSON（含原始特征、两套分数、9 点预测误差），下次真人复测就能直接定性。

| 轮次 | 平均留一误差 | 最大 | 评级 | 误差图形状 |
| --- | --- | --- | --- | --- |
| ①（修复前） | **50.4%** | 82.9% | 偏低 | 全屏乱飞、无结构 |
| ②（修复后第一次） | **10.2%** | 21.1% | 偏低 | 有结构：向中心收缩 + 纵向偏移 |
| ③（修复后第二次） | **6.0%** | 13.6% | **良** | 6/9 点贴近目标，左侧列几乎重合 |
| ④（**同一份 ③ 的样本离线重算**，非新实测） | **4.7%** | **9.8%** | **优** | 与 ③ 同形，只是被 λ 与特征集选择改好了 |
| ⑤ 真机 `03:14:02`（`variant=full`） | **5.2%** | 13.0% | **良** | 形状近乎完美：`px=0.996tx+0.002`、r=0.999、平均偏移 0；样本内误差 2.14%（61 帧/点、抖动 0.00397） |

⚠ **④ 的 4.7% 在真机上没有复现**（⑤ 5.2%、⑥ 6.7%）。原因是「用留一误差同时选超参和评模型」必然带**选择偏差**：离线重算是在同一份数据上挑最好组合，换一份新样本就未必。**所以对外口径只用真机实测值，不用离线重算值。**

### ③ 的 JSON 到手后，发现真正瓶颈是"泛化"而不是"信号"

③ 的导出 JSON 里有一组对照非常关键：**样本内误差 2.14%、留一误差 5.20%（2.4 倍）**，而误差图的形状统计是**斜率 0.996 / 0.991、相关系数 0.999 / 0.997、平均偏移 0.0%**。

翻译过来：这份标定的"形状"是**完美的**（预测范围与目标范围 1:1、几乎无偏移、相关 0.999），**误差全部来自泛化损失**——９ 个点拟合 6 个参数（5 特征 + 截距），留一必然放大。而 `diag.rawStd` 暴露了第二个问题：**标定时头几乎没动**（`faceCx` 跨点标准差只有 0.0014 = 0.14% 画面宽），可是 `faceCx` 的系数却达到 −0.125——也就是说，标定期间那 0.14% 的抖动被 z-score 放大成了权重，**用户演示时头一动 1% 屏宽，光标就会跳 12% 屏宽**。

于是做了两处数据驱动的修改（依据就是扫描这份真人样本）：

| 改动 | 依据（真人样本扫出来的） | 效果 |
| --- | --- | --- |
| 岭系数 λ 从拍死的 0.01 改为在 `LAMBDA_GRID` 上按留一误差自动选 | λ 扫描呈 U 形：0.01 → 5.20%/13.01%；**0.1 → 4.60%/9.77%**；0.3 → 4.70%/7.83%；3 → 10.23% | 平均 −0.6pp、**最大 −3.2pp** |
| 特征集从"1.5 倍倍数"改为 **1-SE 规则**（差距在 1 个标准误内就取参数更少的） | 真机两套只差 0.06pp（4.60% vs 4.66%），se = 0.78% → 判"无显著差别" | 改选**纯眼球模型**（少 2 个噪声参数），演示时头动不再让光标跳 |

重算后：**平均 4.66% / 最大 9.80% / 评级「优」**，诊断文案同时改成诚实版本（"两套精度差别在噪声范围内……已采用纯眼球模型"），并按**最大误差**给建议（平均够好但某角落仍差时，不再笼统说"四角都能命中"，而是点名方位）。

> ⚠ **口径必须诚实**：④ 这一行**不是新的真人实测**，而是把 ③ 的样本拿来重跑改进后的算法；而且 λ 网格的最优点是在这份数据上看过的，存在**选择偏差**，所以 4.66% 是个**偏乐观**的数字。它证明的是"这两个改动方向对"，**不是**"真人精度已达 4.7%"。要坐实这个数字，必须等下一次**独立**标定。

**②③ 证明了修复方向是对的**：误差从"随机"变成"有结构"，说明眼球信号一直都在，之前只是被"z-score 放大噪声 + 头动项主导"淹没了。

**③ 还带来了两个真机验证**（合成数据验证不了的东西）：
- **头动项择优真的会选 full**：诊断显示「含头动项的模型明显更好（6.0% vs 10.3%）」→ 说明这位用户标定时头**确实**有配合移动，头动补偿是有真实信息量的，保留它是正确的（这也印证了 §六 里"头动项不是有害、而是需要多姿势才能辨识"的判断）；
- **离群帧剔除在真机上生效**：诊断显示「已自动剔除 8 个离群帧（眨眼/跳变）」。

**③ 的残余问题（诚实记录）**：误差还有结构，且左右不对称——左侧列三个点几乎重合（最好），右侧的点偏差最大（右中一点约偏 8% 屏宽）。这说明"靠边角的注视点"仍不稳定，所以结果页现在会**点名最差的方位**（例："误差最大的是屏幕右边中间那个点"），现场据此把重要按钮往中心放。

精度口径提醒：界面上的 err 是 `hypot(dx, dy)`，把纵向误差也按"宽度单位"算，**对纵向误差偏乐观**；1080p 下 6.0% ≈ 65px（误差各向同性时约 70–90px），最大 13.6% ≈ 150px。

> 仍未验证：这份 6.0% 的标定是在"坐姿端正、距离固定"下取得的，换姿势后要不要重标、以及"只转头不动眼"是否真的被退化门拦住（对照实验待做），都还没有数据。
>
> **另外三件必须验证的事**：① λ 自动选择与 1-SE 规则需要**下一次独立标定**来确认（现在的 4.66% 有选择偏差）；② 经典的 1-SE 规则要求"误差近似正态"，留一只用 9 个点估标准误，样本很小，规则可能过于激进——真机再标一次就能看出它是否会把本该保留的头动项误删；③ 用户现有 localStorage 里存的是 v3 旧模型（5.2%/良），**新代码不会自动重标**，需要点一次「重新标定」才能拿到改进后的结果（旧模型仍能正常加载使用，不会被拒）。

### 精度预期（务必现场核对）

合成数据实测（同一条代码路径，只换关键点来源）：关键点抖动 ±0.003（约 1280×720 下 2px）时**留一平均误差 ≈3.6%、最大 ≈7%**；样本内误差只有 ≈1.7%，所以报告里**只认留一数字**。

折叠到 1080p：平均 ±3.6% ≈ ±78px，最大 ±7% ≈ ±150px。

**真人实测（六轮，见上）**：修复后稳定落在 **5.2%–6.7% 平均 / 13.0%–17.5% 最大，评级「良」**（最好一轮 6.0%/13.6%）。因此：
- **中心区按钮能稳定注视命中**；**四角（尤其右侧）明显更差**，重要按钮放中间（诊断会点名最差方位）；
- 必须配合已经做好的**目标放大**（`ui.css` 末尾覆盖块）与 800ms 停留确认；
- **头动/换姿势会漂（已量化）**：同一台机器同一个人，两次标定互测误差 **20%–70%**（`eyeDist` 跨会话漂移 0.0217，是会话内信号的约 20 倍）。换姿势、换椅子高度后要重新标定（20 秒）——**这正是「点击即训练」在线学习存在的理由**（见上「在线学习」小节）；
- 界面上的 err 把纵向误差按"宽度单位"算，**偏乐观**；5.2%–6.7% ≈ 1080p 下 ±56–72px（实际约 60–90px）；
- **岭系数 λ 与特征集都从数据里选**（λ 在 `LAMBDA_GRID` 上选、两套特征集按 1-SE 规则二选一），这消除了"拍死 0.01 / 拍死 1.5 倍"的随意性，但**用留一误差同时选超参和评模型会带来选择偏差**，所以对外数字以"独立实测"为准；
- 普通 RGB 摄像头在"头随便动、还想点小按钮"的指标上物理不可达，别写进验收指标；
- 对外口径用真人数字（六轮 5.2%–6.7%，最好一轮 6.0%/良），**不要用合成的 3.6%，也不要用离线重算的 4.7%**；样本量仍是 1 个人 1 次标定，换人换机器都要重新测。

### 在线学习：点击即训练 + 自适应卡尔曼（本轮新增）

**为什么需要它（本轮最重要的一条结论）**：把两次真人标定互测（同一台机器、同一个人、同一套代码），误差是 **20–70%**。根因不是模型不够好，而是**绝对注视本质上只是「某个瞬间的姿势快照」**：

| 量 | 跨会话漂移 | 同一次标定内 9 个点的差异 |
| --- | --- | --- |
| `eyeDist`（脸到摄像头距离） | **+0.0217** | ~0.001 量级 |
| `faceCy` / `faceCx` | +0.0128 / +0.0066 | — |
| `dLx` / `dRx`（虹膜横向） | −0.019 / −0.0179 | — |

漂移量是会话内信号的 **20 倍**量级。离线算法无解（已实测：把姿势项全部压掉仍有 19.7% / 33.5% 误差），唯一出路是**持续标定**——而用户不会愿意反复做 9 点标定，所以只能「顺手点几下就更新」。

**机制（借鉴 WebGazer 的思路，代码全部自研）**：`lib/gaze-online.js`

1. **点击即标签**：每一次真实点击都配成一条样本——输入 = 当帧 8 项面部特征，标签 = 被点按钮的**矩形中心**。停留点击（dwell）走的是同一条 `el.click()` 路径，所以「注视停留选中」也天然产生样本，不是特例；
2. **时间衰减权重**：新样本权重 0.6，按 90 秒半衰期衰减，下限 0.15（`CLICK_WEIGHT` / `CLICK_HALF_LIFE_MS` / `CLICK_WEIGHT_FLOOR`）。老姿势不能永久主导，但也不被完全抹掉；
3. **节流**：至少新增 3 条样本、且距上次重训 ≥3 秒（`RETRAIN_MIN_NEW` / `RETRAIN_MIN_GAP_MS`）。否则每点一下都要跑一遍「N 套特征集 × 5 个 λ × 留一」，会把主线程拖住；
4. **样本池上限 48**：满了淘汰权重最低（最老）的点击样本，**标定样本永不淘汰**；
5. **安全阀（WebGazer 没有的保护）**：新模型必须在**同一份样本集**上不比自己差才允许上线，判据 `nextErr > prevErr × 1.15 + 0.01` 即拒收。加绝对地板是因为标定模型的样本内误差本来只有 0.3% 量级，纯相对阈值会把「0.3% → 0.6%」这种仍然优秀的模型判死；
6. **不自动重训**：样本跨会话存在 `air-runner.gazeSamples`（与模型 `air-runner.gazeModel` 分开），启动时只恢复、不立即重训，等用户下一次点击自然触发。

**安全阀实测**（`.deepworks/tmp/probe-online-guard.mjs`，往真实样本里注入合成「姿势漂移」）：

| 场景 | 新/旧误差比 | 结果 |
| --- | --- | --- |
| 漂移 5 / 12 / 20 条点击 | 1.05 / 0.72 / **0.56** | 放行（样本越多越是净改善）|
| 停留延迟噪声 12 条 | 0.96 | 放行 |
| 系统性误标（眼睛看别处却点了按钮）12 条 | 0.87 | **放行 —— 已知局限** |
| 污染 20 条 | — | 被 `fit` 自身的退化门拦下 |

⚠ **已知局限（不要在对外材料里夸大）**：「系统性误标」与「姿势漂移」在数学上无法区分（两者都是「特征与标签不一致」），所以安全阀挡不住**持续**误标。实际影响有限——正常使用时绝大多数点击都是「想看那个按钮」——但**不要宣称「点错了也不会学坏」**。

**点击样本「怎么点」最有效**（`.deepworks/tmp/probe-click-concentration.mjs` + `probe-click-nonuniform.mjs`，构造合成漂移后评估 25 点网格）：

| 漂移类型 | 点击集中在同一按钮 | 点击分散到全屏 |
| --- | --- | --- |
| **均匀漂移**（整体平移，如往后靠一点） | 3.37% → **0.08%** | 3.37% → **0.02%** |
| **非均匀漂移**（转头/改变距离，屏幕两侧漂移方向相反） | 4.84% → 2.32%，**另一侧残留 2.83%** | 4.84% → **1.42%**（两侧各 ~1.5%） |

三条结论（都只在这两种合成漂移下成立）：

1. **均匀漂移下，任何一条正确点击都能重新锚定全屏**——因为「整体平移」这个信息只出现在任意一条样本里。所以反复点同一个按钮**不会学坏**，只是收益打折。
2. **非均匀漂移下必须分散点**：集中点击只能修好被点的那一侧。等量点击（12 条）分散后 1.04% vs 集中 2.67%，**好约 2.6 倍**。
3. 两种情况下集中点击都**没把别处弄得更差**（仍是净改善）——所以不用担心「点集中了会学坏」，只是效率低。

⇒ 现场建议：**彩排时在屏幕四角 + 中间各点几下**（菜单/教学/结果页的按钮天然分散），比反复点同一个按钮划算。

**自适应卡尔曼平滑**：`lib/kalman.js` 的 `KalmanPoint` 已换成默认平滑器（`?smooth=oneeuro` 可切回对比）。恒速模型 + 速度自适应过程噪声，参数经同机扫描定稿 `q=0.001 / qFast=0.3 / r=0.0009`：

| 指标 | 原 1€(1.6, 0.03) | 卡尔曼 | 变化 |
| --- | --- | --- | --- |
| 停顿抖动 RMS | 0.301% | **0.188%** | −38% |
| 扫视滞后 RMS | 9.145% | **4.722%** | −48% |
| 阶跃 90% 上升时间 | 233ms | 233ms | 不变 |

即**两端同时变好**，不是「更稳但更钝」的取舍。测量噪声 R 还会随标定质量自适应（`rFromAvgErr`：留一误差越大越不信观测）。注：R **故意不按 avgErr² 走**——实测那样扫视滞后会退回 1€ 水平。

**实现位置**：`app.js` 的 `noteGazeClick()` 挂在全局 `onClick` 上，**在动作处理器之前**采样（动作常会切屏，之后再取元素矩形就变成 0 了）；并有两道排除：标定屏的点击不算样本（那是「看向目标点」，标签语义不同）、特征缓存超过 300ms 的陈旧样本丢弃（人脸刚要丢时特征与标签不同步，**坏样本比没样本更坏**）。

### 这轮测试抓出并修掉的真实缺陷

| # | 缺陷 | 后果 |
| --- | --- | --- |
| 1 | `gesture.js` 挥动用「冻结锚点累积位移」 | 回手被判成反向挥动、缓慢漂移误触发（见 §5） |
| 2 | `input.js` 相对路径写成 `../../src/` | 解析到不存在的 `demo/src/`，**浏览器直接加载崩溃** |
| 3 | `runner.js` 循环可重入 | 从设置页返回时叠加多条 rAF 链（越玩越快）、暂停后无法恢复 |
| 4 | `dwell.js` 写 `is-dwelling`，`ui.css` 要的是 `dwl-on` | **注视进度环永远不显示**，注视点击没有视觉反馈（静态检查抓到） |
| 5 | `calib` 9 秒超时每帧调 `forceCalibPass()` | 每帧刷提示与 DOM，超时后按钮判定错乱 |
| 6 | `gaze` 模式仍喂手势 | 挠头/扶脸/拿水杯被判成跳跃 |
| 7 | `?mode=sim` 仍会申请摄像头 | 无设备时会降级成鼠标模式，合成手势链路随之失效（演示模式名不副实） |
| 8 | `?autostart=1&mode=sim` 顶掉自动演示 | kiosk 链接进游戏后没有任何自动操作 |
| 9 | 标定特征原用「眼眶 bbox 内比值」，且**逐帧先算特征再取中位数** | 比值的中位数是**有偏估计**（Jensen 偏差 + 变量误差），标定数据被压缩、预测系统性偏移：实测 y 偏 3.7%、x 斜率偏 5%。改为**先中位数关键点、后算特征**，并换成更大的分母（眼宽归一化位移） |
| 10 | 标定质量分一度用样本内残差 | 6 参数 / 9 点必然乐观（实测样本内 1.7% vs 留一 3.6%，差 2 倍），会让人误判"标得很准"。改为**留一交叉验证**作为唯一对外误差 |
| 11 | `GazeCalibModel.fromJSON` 校验过松 | 空对象/缺字段也能"通过"，坏数据会让光标静默停在 (0.5,0.5)。改为校验版本号、权重长度、有限性、`std>0`、`ok=true` |
| 12 | **`MIN_STD` 只夹分母，从不拒绝标定**（真人实测 50.4% 暴露） | 眼球信号缺失时 z-score 把噪声放大成权重，输出看着正常实则随机，还标 `ok:true`。新增用**未夹取原始标准差**判定的 `MIN_EYE_STD` 退化门 |
| 13 | **头动项无条件进模型**（真人实测 50.4% 暴露） | 用户"转头看角落"时模型学成「头位置 → 屏幕位置」。改为 full/reduced 两套特征集按留一误差自动择优，诊断同时报出两套分数 |
| 14 | **完全没有质量门**（真人实测 50.4% 暴露） | 50.4% 的废模型照样能「应用并返回」，光标满屏乱飞。加 `MAX_ACCEPT_ERR=25%` 上限：超限判失败、应用按钮保持禁用、`fromJSON` 也拒绝加载（含旧 v2 格式），并在测试里钉死「失败标定不顶掉已生效旧模型」 |
| 15 | 标定结果只有一行数字，**没有任何排查手段**（真人实测 50.4% 暴露） | 出问题时只能看到一个"50.4%"，无法判断是特征、光线还是动作问题。补 `diag`（每点帧数/抖动/头部极差/离群帧数）+ 结果页多行中文诊断 +「复制诊断数据」导出结构化 JSON |
| 16 | 眼睛特征用上下眼睑中点算眼眶中心 | 眨眼/眯眼会污染眼眶中心。改用内外眼角 y 中点（对合成数据无影响，真机更稳） |
| 17 | 「有效点不足」把所有失败原因说成一句话 | 用户不知道该改什么。改为按 `insufficient/singular/weak-eye-signal/poor-fit` 分别给可操作建议 |
| 18 | 岭系数 λ 拍死 0.01，没有依据（真机 JSON 暴露） | 用真人 9 点样本扫 λ 得到 U 形曲线：λ=0.01 → 5.20%/13.01%，λ=0.1 → 4.60%/9.77%。λ 太小会把"标定时几乎不变的特征"（faceCx 跨点 std 仅 0.0014）用 z-score 放大成噪声权重。改为在 `LAMBDA_GRID` 上按留一误差自动选 |
| 19 | 凭「1.5 倍」这个拍出来的倍数决定要不要保留头动项（真机 JSON 暴露） | 真机上两套只差 0.06pp（4.60% vs 4.66%），却被判成"含头动项明显更好"，于是保留了 2 个噪声里拟合出来的参数——演示时头一动光标就跳。改为标准做法（Breiman 的 1-SE 规则）：差距在 1 个标准误内就取参数更少的那套，并用同一个尺度重写诊断文案 |
| 20 | 在线学习上线后，「没有点击样本」的路径必须**逐位等同旧行为** | 否则已标定用户升级后精度会变（"差不多"不算数）。实现上用加权最小二乘兜底：无点击样本 ⇒ `sampleWeights` 返回 `null` ⇒ 全程走无权重旧路径，并在测试里逐位断言（而不是"误差接近"） |
| 21 | **测试台合成夹具用了 `Math.random`**（本轮交叉核对文档数字时发现） | 留一误差在 2.2%–4.4% 之间随机漂移，连带「评级」文案变化、**两条依赖评级的断言时有时无**（PASS 计数 159–161 抖动），且约 4/30 个种子会因最坏点 5.01–5.28% 卡在 5% 门限上偶发失败——**测试会因为"抽签"而红，不能当回归基线**。修法：①播种 LCG 取代 `Math.random`；②门限按夹具噪声地板重定（合成帧噪声 0.003≈2px，9 点最坏点固有 ~5%，5% 卡边界 → 6%）；③依赖评级的断言改为**无条件一条**（断言数与数据无关）；④方位词补「正中」——最差点落在屏幕中心时诊断写的是「屏幕正中那个点」，原正则只认 `角`/`边中间`，会误报 |
| 22 | 诊断文案的方位词与断言口径不一致（由上一条暴露） | 这不是产品 bug（「屏幕正中那个点」对用户是可读且正确的），而是**测试正则漏了「正中」这一支**。按产品文案为准修正断言，避免"为了让测试过而改文案" |

⚠ **未能验证**：真实摄像头链路（FaceMesh/Hands 实际关键点质量、坐姿下挥动识别的真实误触发率、三区注视在真人身上的命中率）。本机双模态实拍数据缺失，需同学在实机跑一次并回填数据。

⚠ **真人实测共六轮**（50.4% 废 → 10.2% 偏低 → 6.0 / 5.2 / 6.7% 良，见 §六）：上表 12–15 是第一次失败逼出来的修复，后续各轮证明修复有效。**「换姿势后精度会漂多少」现已量化**：同一台机器同一个人，两次标定互测 **20%–70%**（`eyeDist` 跨会话漂移 0.0217 ≈ 会话内信号的 20 倍）——这就是「点击即训练」在线学习的动机，也说明**它不属于「算法能修好」的问题，只能靠持续标定**。**「只转头不动眼」被退化门拦下**已有自动化回归覆盖（合成事故样本 → `weak-eye-signal`/`poor-fit`）。样本量仍是 1 人 1 台机器，不能外推。

## 十、彩排清单（建议现场前跑 3 遍）

1. **彩排 1 · 双模态正常路径**：默认链接。确认摄像头权限、距离 0.6–1.0m、光线充足；走完首屏 → 模式 → 就位校准（4 项打勾）→ 教学 4 项（约 10 秒）→ 玩满一局 → 导出战绩卡。记录：一局里**误触发几次**（没挥手自己跳/自己滑铲）、注视变道平均耗时。
2. **彩排 2 · 单模态对照**：分别用 `?mode=gaze`（只动眼）与 `?mode=hand`（只动手）各跑一局，**拍板现场主推哪一版**；顺手验证 `hand` 模式下左右挥变道的手感，以及 `gaze` 模式下举手挠头确实不会跳。
3. **彩排 3 · 断网/无设备降级**：拒绝摄像头权限 / 拔掉摄像头 → 确认自动进鼠标模式不黑屏；再打开 `?mode=sim` 确认自动演示能跑完整流程；离线场景需提前把 MediaPipe CDN 三个脚本本地化（当前依赖 jsdelivr）。

4. **彩排 4 · 9 点标定（本轮重点，已改）**：设置页点「重新标定」（或 `?gazecal=1`）→ 坐正、**只动眼睛不转头**，跟完 9 个点（约 20 秒）→ 读多行诊断：
   - 若显示「可用」：看误差图（预测叉是否都贴着圆点）、记下平均/最大误差、读诊断点名的「最差方位」（据此调整按钮摆放），应用返回后确认设置页状态行「已标定 9 点 · 留一误差 平均 X% / 最大 Y% · 评级 Z」，再中心区试注视几个按钮记命中率；
   - 若显示失败（按钮保持禁用，**不会**给出乱飞光标）：点「复制诊断数据」把 JSON 回传，先别应用；
   - 复测完必做一次**对照实验**：故意只转头不动眼标定一次，确认界面**拒绝**这次标定（这是本轮修复的核心保证）。
   无摄像头时用 `?mode=sim&gazecal=1` 看流程但不落盘。
   - **顺手验证在线学习（本轮新增）**：标定完成后正常玩几局（每次点击、以及每次停留选中，都会自动采一条样本）→ 回设置页看状态行是否出现「已累积 N 条点击样本」；若模型被在线更新会弹一条吐司（「注视模型已在线更新」）。想对比效果就另开 `?train=0`（关在线学习）玩同样时长，比较跟手程度与命中率。

5. **彩排 5 · 平滑器 A/B（本轮新增）**：默认（卡尔曼）与 `?smooth=oneeuro` 各玩一局，重点感受**停顿时光标是否还在抖**与**快速扫视是否跟手**。理论上卡尔曼两端都更好（停顿抖动 −38%、扫视滞后 −48%、阶跃上升时间不变）。若上台前觉得偏"飘"或偏"钝"，直接换 `?smooth=oneeuro` 回退，**不需要改代码**。

现场速记：**看左/看右/看中间 = 变道；向上挥 = 跳；向下挥 = 滑铲；握拳 = 护盾**；注视模型默认**在线学习开启**（正常玩就会自己变准，若不顺手加 `?train=0` 关掉）；不顺就按 `?mode=mouse` 或直接用键盘（←→↑↓空格F）兜底，键盘路径和手势走的是同一套游戏逻辑，不会「手势不行就没法演示」。
