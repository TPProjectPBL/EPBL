# 眼动 + 手势跑酷 · Air Runner

三车道跑酷 Demo：**眼动选车道 / 手势跳跃与滑铲 / 注视停留点击**。纯前端（原生 ESM + Canvas），无构建、无框架。

> 维护者：[@Evelyn11290000](https://github.com/Evelyn11290000)
> 详细交付说明、22 条缺陷记录与红线自查见 [`docs/眼动手势跑酷Demo-交付说明与红线自查.md`](../../../docs/眼动手势跑酷Demo-交付说明与红线自查.md)

## 运行

`getUserMedia` 只在安全上下文可用，**不能双击打开 `index.html`**。

```bash
# 在仓库根目录执行
python3 -m http.server 8130
```

浏览器打开：

```
http://127.0.0.1:8130/eye-page-turner/demo/air-runner/index.html
```

首次打开需允许摄像头权限。

## 模式与参数

| 模式 | 说明 |
|---|---|
| `dual` | 眼动 + 手势同时可用（默认） |
| `gaze` | 只保留眼动，手势完全屏蔽 |
| `hand` | 只保留手势 |
| `mouse` | 无设备时的鼠标兜底 |

URL 参数：`?mode=sim`（无设备自动演示）、`?autostart=1`（直接进局）、`?train=0`（关闭点击即训练）、`?smooth=oneeuro`（切回旧平滑器对比）。

## 目录

| 文件 | 职责 |
|---|---|
| `index.html` | 10 个 `section[data-screen]` + 全局层（摄像头预览、光标、吐司、暂停弹层） |
| `ui.css` | 视觉基线；注视进度环、三区注视条、标定屏样式 |
| `app.js` | 编排层：采集 → 平滑 → 手势/注视事件 → 屏幕路由 → 游戏驱动；9 点标定状态机；点击即训练 |
| `lib/input.js` | 统一输入出口（复用 air-draw 的平滑/光标源 + `src/*` 采集模块） |
| `lib/router.js` | 屏幕路由（`go/back/replace/has/canGoBack`） |
| `lib/dwell.js` | 注视点击（dwell 800ms + 速度门限） |
| `lib/gesture.js` | 挥手/握拳状态机（滑窗 280ms、停稳重新武装、480ms 冷却） |
| `lib/runner.js` | 三车道跑酷逻辑（跳跃/滑铲/护盾/计分/难度） |
| `lib/gaze-zone.js` | 三区注视选择（累积/重置/冷却） |
| `lib/gaze-calib.js` | 9 点标定：中位数 → MAD 去离群 → 加权岭回归 → 留一评估 → 退化门 |

| `lib/kalman.js` | 自适应卡尔曼平滑（`q=0.001 / qFast=0.3 / r=0.0009`） |

## 已知问题与限制

| 问题 | 状态 | 说明 |
|---|---|---|
| 挥手误触发率 | ⚠ 待实机标定 | 机制已就位（滑窗 280ms + 停稳重新武装 + 480ms 冷却 + 三档灵敏度），缺真人误触发/漏触发的实测数字 |
| 注视变道成功率与耗时 | ⚠ 待人力实测 | 单元层面已验证累积/重置/冷却，缺「看向目标车道 → 变道」的真人成功率 |
| 绝对注视点精度 | ⚠ 六轮真人实测平均 5.2%–6.7%、最大 13.0%–17.5%，评级「良」 | 约 1080p 下 ±56–72px；**中心区可用，四角（尤其右侧）明显更差**，重要按钮放中心 |
| 头动污染 | ⚠ 因果待验证 | 第 7 次真机在「脸近一倍 + 头动 12 倍」条件下退化到 11.8%；n=3 且距离与头动同时变化，需「坐回原距离 + 头顶稳住」重标一次验证 |
| 换姿势后漂移 | 已知，算法修不好 | 同一人同机器两次标定互测误差 20%–70%，只能靠重新标定 + 点击即训练缓解 |
| 系统性误标 | 已知局限 | 「眼睛看别处却点了按钮」与「姿势漂移」在数学上不可分，安全阀挡不住**持续**误标；不要宣称「点错了也不会学坏」 |
| 标定问题无法离线复现 | 已知 | 导出 JSON 只存逐点聚合值、没有逐帧序列，头动污染类问题只能真机重标验证 |

## 未验证

- 真实摄像头链路下 FaceMesh / Hands 的关键点质量；
- 坐姿下挥手识别的真实误触发率；
- 三区注视在真人身上的命中率；
- 样本量目前是 1 人 1 台机器，不能外推。
