01摘要

本插件将原「眼动翻页」方案升级为「手势 + 眼神」双模态翻页插件：一段嵌入宿主网页的前端脚本/组件，通过用户设备摄像头自动判断人与屏幕的距离，远距离（≥1.5m）用手势控制、近距离（<1.5m）用眼神控制，无需点击翻页按键即可完成上下左右翻页/滚动。

核心架构结论：识别全程在用户本地浏览器前端执行（摄像头数据与推理不出设备）；「后端运行的插件」指「运行在宿主页面运行时中的客户端插件」。双模态通过距离估计 → 模式切换器统一调度，两个分支共用动作执行器与宿主适配层。

远距离 ≥ 1.5m

手势控制：MediaPipe Hands 检测手部关键点，识别挥动/滑动方向，映射上下左右翻页。适合演讲、大屏演示、站立远距离操作。

近距离 < 1.5m

眼神控制：MediaPipe Face Mesh + Iris 检测虹膜关键点，估计注视方向，驻留触发翻页。适合桌面阅读、PDF/文档精细操作。

一句话结论 getUserMedia 取摄像头 → Face Mesh（人脸/虹膜 + 距离估计）与 Hands（手势）并行检测 → 距离 ≥1.5m 走手势分支、<1.5m 走眼神分支 → 平滑/触发 → 统一动作执行器驱动宿主翻页。纯前端、零数据上传、HTTPS 强制。

关键指标（第一阶段）

  • 距离切换阈值：1.5m（迟滞带 ±0.2m）
  • 眼神方向：上/下/左/右 + 中心，准确率 ≥ 90%
  • 手势方向：上/下/左/右挥动，准确率 ≥ 90%
  • 帧率：桌面 ≥ 30 FPS，移动端 ≥ 20 FPS
  • 触发延迟：驻留 500–1000ms / 手势挥动即时

关键约束

  • HTTPS / localhost：getUserMedia 仅安全上下文可用
  • 需用户显式授予摄像头权限
  • 需前置摄像头；手势模式需手部在画面内
  • 距离估计需一次性标定，误差需受控

02背景与目标

2.1 变更背景

方案由原生 iOS App 转向 Web 端交互页面插件。在「眼动翻页」基础上，产品进一步明确交互边界：近距离用眼神、远距离用手势，以 1.5 米为分界，使插件在桌面阅读与远距离演示两种典型场景下都自然可用。

2.2 核心目标

  • 提供可嵌入网页、开箱即用的双模态翻页能力，替代点击翻页按键。
  • 按距离自动切换：≥1.5m 手势、<1.5m 眼神，用户无需手动切换。
  • 第一阶段覆盖上下左右四方向翻页，形成可演示、可验收的 MVP。

2.3 成功标准（MVP）

  • 宿主页面引入脚本后，授权摄像头即可使用：走近用眼神、走远用手势翻页。
  • 距离切换平滑、有 UI 提示、不产生误触发。
  • 翻页动作可由宿主通过回调/事件自定义。
  • 权限拒绝、无设备、无手/无人脸、低置信度等异常均有明确反馈与降级。

03需求确认

3.1 产品定位

面向网页的「手势 + 眼神」双模态翻页交互插件：用户浏览演示文稿、PDF、电子书、长文页面时，根据距离自动采用手势或眼神翻页，实现免手/免按键操作与无障碍交互。

3.2 可采用的插件形态

形态说明优点适用
A. 嵌入式 JS SDK宿主引入 <script>，暴露全局 API，配置「方向→动作」映射。集成轻、可控强自有网站/产品
B. Web Component 组件封装为 <eye-page-turner>，Shadow DOM 隔离。组件化、可复用组件化工程
C. 浏览器扩展Content Script 注入任意站点。跨站通用通用阅读/演示工具
D. 悬浮控制面板注入悬浮 UI，模拟键盘/点击驱动宿主。侵入性低演示/快速验证
推荐方案 以 A（SDK）+ B（Web Component） 为主形态，C（浏览器扩展） 后续复用同一核心；D 作为 A 内部默认动作策略。

04可行性分析

4.1 技术可行性 高

  • 摄像头采集、Face Mesh（人脸/虹膜）、Hands（手势）均有官方浏览器 WASM/WebGL 实现，成熟稳定。
  • 眼神四方向为粗粒度分类，几何规则即可达可用精度；手势挥动方向识别同样属于低复杂度分类。
  • 距离估计可用「瞳距/脸宽尺度法」实现，误差对 1.5m 阈值判断（配迟滞带）影响可控。

4.2 硬件可行性 高

  • 笔记本/一体机/手机/平板普遍带前置摄像头；外接摄像头亦可。
  • 远距离手势需手部在取景范围内，前置广角通常可覆盖 1.5–3m。

4.3 距离估计可行性 中

  • 单目距离估计依赖尺度基准（瞳距/脸宽）与一次标定，个体差异（瞳距 55–70mm）会引入误差。
  • 缓解：默认取 63mm 平均瞳距 + 可选个体标定；仅在 1.5m 阈值附近需要较高精度，迟滞带吸收抖动。

4.4 合规与权限 中

  • getUserMedia 仅安全上下文可用；权限拒绝即不可用，需降级。

4.5 结论

双模态方案在技术、硬件层面完全可行，主要风险集中在距离估计精度、模式切换抖动、光照鲁棒性与低端设备性能，均可通过标定、迟滞、阈值与降级策略控制。建议启动 MVP。

05整体架构

插件为纯客户端前端应用。宿主页面加载脚本后，插件内部完成采集、双路检测（人脸/手势）、距离估计与模式切换、各自触发，最终通过统一适配层驱动宿主交互。

5.1 数据流

摄像头帧 → 采集层（getUserMedia） → [并行] 人脸检测（Face Mesh + Iris → 关键点 + 距离估计）｜ 手势检测（Hands → 手部关键点） → 模式切换器（距离 ≥1.5m → 手势；<1.5m → 眼神；迟滞防抖） → 眼神分支（方向估计 → 平滑 → 驻留触发）｜ 手势分支（方向识别 → 速度阈值 → 触发） → 动作执行层（方向→动作映射：click / scroll / keyboard） → 宿主适配层（CustomEvent 派发 + 全局 API 回调）

5.2 部署形态

  • 自托管：宿主引入 eye-page-turner.umd.js，模型托管自有/CDN。
  • CDN / npm：发布到 npm + CDN，一行脚本引入。
  • 浏览器扩展：同一核心打包为扩展（后续阶段）。

07关键技术选型

领域选型理由
开发语言TypeScript类型安全、SDK 化、IDE 提示。
摄像头采集MediaDevices.getUserMedia浏览器原生、无依赖、标准 API。
人脸/虹膜检测MediaPipe Face Mesh + Iris官方 WASM/WebGL 实时方案，自带虹膜点支撑视线估计。
手势检测MediaPipe Hands（21 点）官方实时手势关键点，成熟、轻量，支持轨迹/方向识别。
距离估计瞳距/脸宽尺度法 + 一次标定单目可用、低算力；误差由迟滞带与个体标定吸收。
前端推理运行时@mediapipe/tasks-vision（TF.js 备选）SIMD/WebGL 加速、体积可控、官方维护。
视线方向估计几何规则（虹膜偏移 + 头部补偿）四方向粗分类无需重模型，透明低延迟，易调优。
手势方向识别手部关键点轨迹 + 速度/位移阈值挥动方向简单可靠，避免重模型训练。
平滑/触发滑动窗口 + 驻留状态机 / 手势阈值抑制抖动与误触，成熟模式。
动作执行原生 DOM（click/scroll/KeyboardEvent）无依赖，可驱动任意宿主翻页。
组件封装Web Components（Custom Elements + Shadow DOM）样式隔离、跨框架复用。
构建打包Vite（library mode）→ ESM + UMD/IIFE同时支持模块化与 script 直引。
宿主通信DOM CustomEvent + 全局 API解耦、无框架依赖。
模型分发CDN 懒加载（.task/.tflite/WASM）SDK 与模型分离，控制首屏体积。
备选说明 距离估计备选：MediaPipe facialTransformationMatrixes 的 tz 分量（相对距离）或脸框面积法；手势识别备选：轻量 MLP/TF.js 自定义手势模型。Safari 需关注 WASM SIMD 与 WebGL 差异，纳入兼容矩阵。

08风险点

风险影响概率应对与缓解
距离估计误差导致模式误切换高中瞳距标定 + 迟滞带 ±0.2m + 连续多帧确认才切换。
摄像头权限拒绝/无设备高中权限引导 + 拒绝降级提示。
非 HTTPS 无法采集高中强制 HTTPS；开发 localhost。
光照差/遮挡导致眼神误判中中置信度阈值 + 低置信丢弃 + 提示。
手势误触（无意挥动翻页）中中速度/位移阈值 + 触发冷却 + 中心中性区。
模式切换瞬间误触发中中切换时动作冷却 + UI 提示。
低端设备帧率不足（双模型并行）中中按当前模式只跑所需模型 + 检测降帧/降分辨率。
浏览器兼容差异中中兼容矩阵 + 特性检测 + 回退。
插件与宿主样式/脚本冲突中低Shadow DOM + 命名空间 + IIFE。
隐私合规质疑高低明确本地处理不上传 + 隐私说明 + 开关。
SDK 体积影响加载中低模型懒加载、gzip、tree-shaking。

09可扩展性

  • 距离分档：1.5m 单阈值 → 多距离段（近/中/远）对应不同交互策略。
  • 方向粒度：四方向 → 九宫格 → 连续注视点。
  • 手势类型：挥动方向 → 静态手势（握拳确认/张掌暂停）→ 手势语义。
  • 动作类型：翻页 → 滚动 → 点击 → 返回/缩放。
  • 触发方式：驻留 → 眨眼/点头 → 语音协同。
  • 能力复用：Face Mesh 关键点可扩展疲劳监测（EAR/PERCLOS）、表情/情绪。
  • 分发形态：SDK → Web Component → 浏览器扩展 → 桌面端（Electron），共享核心。
  • 模型升级：检测层接口隔离，可替换自训练模型或云辅助（需隐私评审）。

10安全性

  • 数据不出设备：画面与关键点仅本地内存处理，不上传（默认）。
  • 仅安全上下文：非 HTTPS（除 localhost）拒绝启动。
  • 权限最小化：仅摄像头权限，不用麦克风；可随时撤销，插件监听并降级。
  • 透明可控：明显开关与状态指示，一键停止采集。
  • 遥测 opt-in：仅匿名事件级、无图像，默认关闭。
  • 宿主隔离：Shadow DOM 防样式污染；全局符号最小化；CSP nonce 接入说明。
  • 依赖安全：锁定版本、npm audit、模型文件完整性校验。
