System Design Report · 系统设计报告

隔空控制器（Air Controller）

后端运作的非接触控制器：以视线控制鼠标移动、以隔空手势控制缩放（张开手放大、握拳缩小）。本报告确认需求，分析可行性、整体架构、模块划分、技术选型、风险、可扩展性、安全性与分步实现/验收，用于指导后续开发。

文档版本 v1.0 状态：需求确认 + 总体设计 日期 2026-10-17 目标平台：macOS 优先（跨平台可扩展） 控制端：Python 后端 + OS API 展示端：浏览器网页（Apple 风格）

1需求确认

将项目定位为「后端运作的控制器」：以普通摄像头识别眼动与手势，由本地后端进程通过操作系统 API 控制鼠标与缩放，前端网页仅作测试展示与状态反馈，不干扰前台操作。

1.1 核心需求

编号需求优先级
F1眼动追踪：以视线控制鼠标移动（操作系统级光标）。P0 核心
F2隔空手势：张开手 → 放大；握拳 → 缩小。P0 核心
F3测试展示网页：白底、黑色圆角按键、Apple 风格，放置能体现功能的交互元素。P0 核心
F4后端运作：控制逻辑在本地后端进程运行，可操作系统鼠标 / 缩放。P0 核心
F5状态反馈：实时显示检测状态、注视点、手势状态、缩放级别。P1

1.2 需求澄清与默认约定

  • 「控制鼠标」指操作系统级真实光标：浏览器安全沙箱禁止网页 JS 直接移动系统鼠标，因此必须由本地后端通过 OS API 执行（见 2.1）。
  • 「后端运作」：动作执行（鼠标移动、缩放）在后端进程完成；前端负责采集 / 检测 / 展示，二者通过本地 WebSocket 通信。
  • 缩放对象：MVP 同时支持「应用内缩放」（前端测试页元素 scale）与「系统缩放」（后端模拟滚轮 / 快捷键），前者用于无后端时演示，后者为最终目标。
  • 运行环境：以 macOS 优先（开发机为 macOS）；后端 OS 控制 API 选用跨平台库，Windows / Linux 可迁移。

2可行性分析

2.1 技术可行性

关键点结论依据
眼动追踪可行MediaPipe Face Mesh 提供虹膜关键点（Iris，468–477），结合头部姿态可估计注视方向；普通摄像头即可，无需专用眼动仪。
系统鼠标控制可行，但需后端网页 JS 受安全沙箱限制无法移动系统光标；Python 的 pyautogui / pynput 可跨平台控制鼠标。
手势缩放可行MediaPipe Hands 输出 21 个手部关键点，可由手指伸直度判定「张开 / 握拳」。
前端 ↔ 后端通信可行WebSocket 低延迟双向，适合连续坐标流上报。

2.2 关键约束与难点

macOS 权限：pyautogui / pynput 移动鼠标需授予「辅助功能（Accessibility）」权限，否则调用会被系统拒绝。这是后端控制的首要环境障碍，需在实现步骤中优先处理并验证。
  • 精度：普通摄像头无标定下注视点估计存在误差（约百像素级），需采用「相对移动 + 平滑 + 死区」策略，避免光标抖动。
  • 坐标系映射：前端归一化坐标 → 后端屏幕像素坐标，需考虑屏幕分辨率、浏览器窗口位置、多显示器。
  • 延迟：检测 + 通信 + 平滑链路需控制在可接受范围（目标 < 100 ms 增量响应）。

2.3 结论

技术路线可行，主要风险集中在系统权限与眼动精度两点，均可通过「先前端自包含演示、再接入后端控制」的分步策略控制风险（见第 9 章）。

3整体架构

采用前后端分离架构：前端负责采集与检测，后端负责指令执行。

┌───────────────────────────────┐          ┌──────────────────────────────────┐
│  前端（浏览器 · 测试展示页）        │          │  后端控制器（Python · 本地进程）      │
│  ─────────────────────────────  │ WebSocket │  ────────────────────────────────  │
│  摄像头采集 (getUserMedia)       │ ───────▶  │  指令解析与平滑 (EMA / 死区 / 防抖)    │
│  眼动检测 (Face Mesh + Iris)     │ 归一化坐标 │  坐标映射 (归一化 → 屏幕像素)          │
│  手势检测 (Hands 21 点)          │ 手势状态   │  鼠标执行 (pyautogui 移动 / 滚轮)      │
│  指令生成 (平滑 / 死区)           │           │  缩放执行 (滚轮 / 快捷键)             │
│  测试台 UI (Apple 风格按键)       │ ◀───────  │  状态回传 (缩放级别 / 心跳)            │
└───────────────────────────────┘          └──────────────────────────────────┘
                      摄像头画面与生物特征全程本地处理，不出设备

3.1 数据流

  1. 前端摄像头取帧，MediaPipe 并行检测人脸（含虹膜）与手部。
  2. 眼动：由虹膜相对眼眶偏移 + 头部姿态，生成「光标增量向量」。
  3. 手势：由 5 指伸直度判定状态（张开 / 握拳 / 无），生成「缩放指令」。
  4. 前端经 WebSocket 将增量向量与手势状态实时上报后端。
  5. 后端做平滑与死区过滤，映射为屏幕坐标，pyautogui 移动鼠标；手势触发滚轮 / 快捷键缩放。
  6. 后端回传缩放级别、运行状态，前端实时显示。

3.2 两阶段演进

阶段检测位置说明
阶段一（MVP）前端（浏览器 MediaPipe）复用现有前端技术栈，快速验证链路；后端只做执行。
阶段二（增强）后端（Python mediapipe + opencv）检测下沉，前端纯展示，真正「后端运作」、不依赖浏览器窗口。

4模块划分

4.1 前端模块

模块职责
采集模块getUserMedia 取摄像头视频流，输出到检测器与预览。
眼动检测模块Face Mesh（refineLandmarks 开启）输出虹膜关键点，计算虹膜相对眼眶偏移。
手势检测模块Hands 输出 21 点，计算手指伸直度，判定张开 / 握拳。
指令生成模块将检测结果转为「光标增量向量 + 手势状态」，做平滑、死区、冷却。
通信模块WebSocket 上报指令、接收后端状态回传。
测试台 UI 模块Apple 风格页面：黑色圆角按键网格、可缩放内容卡片、视线光标、状态面板。

4.2 后端模块

模块职责
通信服务FastAPI / websockets 提供 WebSocket 端点，接收前端指令流。
指令解析与平滑对增量向量做 EMA 平滑、死区过滤、限速（防止光标瞬移）。
坐标映射归一化增量 → 屏幕像素增量；读取屏幕尺寸（支持缩放因子）。
鼠标控制pyautogui 移动光标、点击、滚轮。
缩放控制张开手 / 握拳映射为滚轮（scroll）或 Ctrl+加减 缩放。
权限检查启动时检测并提示 macOS「辅助功能」权限。

5技术选型与理由

技术项选型选型理由
眼动追踪MediaPipe Face Mesh + Iris虹膜关键点成熟、免标定、CDN 直接引入；与既有项目技术栈一致，降低迁移成本。
手势识别MediaPipe Hands21 点手部关键点，判定手指伸直 / 弯曲可靠，社区成熟。
前端通信WebSocket（原生）低延迟双向、连续坐标流场景合适；浏览器原生支持，无需额外依赖。
后端框架Python + FastAPI + uvicorn（或 websockets）轻量、异步高并发、WebSocket 支持好，生态成熟。
OS 控制pyautogui（移动 / 滚轮）+ pynput（可选）跨平台（macOS / Windows / Linux）、API 简洁、社区成熟。
阶段二检测Python mediapipe + opencv将检测下沉后端，实现「后端运作」、不依赖浏览器。
眼动映射策略：MVP 采用「相对移动」模式——视线偏移方向驱动光标增量移动（类轨迹球），避免绝对坐标标定的复杂度；后续可选 WebGazer.js 回归模型做「绝对注视点」校准增强。

6风险点与应对

风险影响应对
macOS 辅助功能权限后端无法移动鼠标步骤 4 优先验证；启动时检测权限并给出引导说明。
眼动精度不足 / 抖动光标漂移、难对准相对移动 + EMA 平滑 + 死区 + 限速；可选校准增强。
光照 / 佩戴眼镜检测失败或误判置信度门限、失败降级提示、状态实时反馈。
坐标系映射偏差光标位置错位读取屏幕尺寸与缩放因子；后续支持浏览器窗口定位。
缩放指令冲突系统缩放与应用内缩放打架提供缩放模式切换；MVP 默认应用内缩放、系统缩放独立开关。
隐私顾虑用户拒绝摄像头全程本地处理、不上传；明示隐私边界。

7可扩展性

  • 更多手势：捏合缩放、挥手翻页、单指点击、拖拽，复用 Hands 关键点新增分类即可。
  • 更多控制目标：键盘输入、系统音量 / 亮度、窗口管理，统一走「指令 → OS API」后端执行层。
  • 检测下沉后端：阶段二把 MediaPipe 移到 Python，前端退化为纯展示 / 遥控面板。
  • 参数化配置：灵敏度、死区、平滑系数、手势阈值集中配置，支持热更新。
  • 多屏 / 多设备：坐标映射层抽象，支持多显示器与多分辨率。

8安全性

  • 本地闭环：后端仅监听 127.0.0.1，不接受外部网络连接，防止远程控制。
  • 数据本地化：摄像头画面与生物特征仅在本地处理，不上传、不落盘。
  • 最小权限：仅申请鼠标 / 键盘控制所需权限，不申请多余权限。
  • 认证（可选）：本地 WebSocket 加一次性 token，避免其他本地进程误连。
  • 安全上下文：前端摄像头访问仅通过 localhost / HTTPS。

9实现步骤与验收

采用「前端自包含演示 → 后端控制接入 → 端到端联调」的分步推进，每步独立可测、可验收。

步骤 1 · 测试台 UI（Apple 风格）

搭建白底、黑色圆角按键网格、可缩放内容卡片、视线光标、状态面板的前端页面。

测试：静态打开页面，逐键 hover / 点击，缩放卡片手动缩放。
验收：白底黑圆角键呈现 Apple 风格；按键 hover 变暗、点击有反馈；无布局错乱。

步骤 2 · 眼动检测 + 视线光标（网页内）

接入 Face Mesh Iris，虹膜相对眼眶偏移生成增量向量，驱动网页内「视线光标」移动；悬停按键高亮，停留驻留触发点击。

测试：授权摄像头，上下左右转动眼球，观察光标是否随视线方向移动、悬停是否高亮。
验收：光标随视线平滑移动（EMA 平滑、无明显抖动）；悬停按键高亮；驻留 ≥ 0.8 s 触发点击。

步骤 3 · 手势检测 + 缩放（网页内）

接入 Hands，计算 5 指伸直度判定张开 / 握拳，驱动内容卡片 scale 放大 / 缩小。

测试：对镜头张开手掌、握拳，观察卡片缩放与状态面板的「张开 / 握拳」判定。
验收：张开手持续放大、握拳持续缩小；松开（无手）停止；缩放比例实时显示、限幅保护。

步骤 4 · 后端服务 + 系统鼠标控制

搭建 Python WebSocket 服务，接入 pyautogui，实现「增量向量 → 屏幕像素移动」，并检测 macOS 辅助功能权限。

测试：用测试脚本向后端发送固定增量，观察系统光标是否移动。
验收：后端能移动系统鼠标；未授权时给出明确权限提示；仅监听 127.0.0.1。

步骤 5 · 前后端联调（视线 → 系统鼠标）

前端 WebSocket 上报增量向量，后端执行系统鼠标移动；状态回传前端显示。

测试：转动眼球，系统光标跟随移动；对照前端「视线光标」与系统光标。
验收：端到端增量响应 < 100 ms；系统光标移动方向与视线一致；有死区与限速防抖。

步骤 6 · 手势 → 系统缩放

张开手 / 握拳经后端映射为滚轮（scroll）或 Ctrl+加减，实现系统缩放。

测试：对镜头张开 / 握拳，观察系统缩放（浏览器缩放、桌面图标等）变化。
验收：张开手放大、握拳缩小；缩放连续且有限幅；支持应用内 / 系统两种模式切换。

步骤 7 · 端到端验收

全链路联调：眼动 + 手势同时运行，测试台按键作为交互目标，完整走查所有功能。

测试：真实用户操作，视线将系统光标移动到目标按键并触发，手势缩放内容卡片与系统缩放。
验收：达到第 10 章验收指标；异常（无脸 / 无手 / 权限拒绝 / 低置信度）均有明确反馈与降级。

10里程碑与验收汇总

里程碑内容验收标准
M1测试台 UI + 眼动光标 + 网页内手势缩放（步骤 1–3）无后端即可在网页内演示两种能力。
M2后端鼠标 / 缩放控制（步骤 4）后端可移动系统鼠标、可触发缩放。
M3前后端联调（步骤 5–6）视线驱动系统鼠标、手势驱动系统缩放。
M4端到端验收（步骤 7）真实用户盲测通过。
