## 1. 冻结原则

1. **口径先于实现**：本单冻结前不写业务代码，冻结后任何口径变更走评审流程。
2. **可量化**：所有指标必须能被第三方按同一方法复现，避免"感觉更流畅"这类描述。
3. **档位 0 优先**：任何需要后端的指标一律排除在首发之外。
4. **场景中立**：不以某一单一场景（演示 / 阅读 / 无障碍）的专属需求设定指标。

---

## 2. 八个决策门（**未否决即按默认值执行**）

| # | 决策门 | 建议默认值 | 影响 |
|---|---|---|---|
| **D1** | 延迟口径定义 | 端到端 = **输入事件触发 → 画面更新完成**；取 P95 ≤ 100 ms，目标 ≤ 50 ms | 验收争议源头，必须先定 |
| **D2** | 方向维度 | 首发**仅四方向**（上 / 下 / 左 / 右）；八方向延后 | 判定逻辑与 UI 密度 |
| **D3** | 支持内容形态 | 支持**分页式内容**：PDF 渲染页、图片集、内置演示页、可嵌入 iframe | 决定"任意页面"的含义 |
| **D4** | 输入方式 | 首发三种：**键盘方向键 / 触屏滑动 / 鼠标滚轮与拖拽**；外接设备延后 | 开发量与测试矩阵 |
| **D5** | 浏览器与设备基线 | Chrome / Edge / Safari **最近两个大版本**；**桌面 + 移动端均纳入验收**，移动端以触屏滑动为主交互并要求自适应可用 | 兼容性验收范围与测试矩阵 |
| **D6** | "适配任意页面"的实现 | 首发做**可嵌入脚本（embed script）**；书签小工具（bookmarklet）作为备选；**不做浏览器扩展** | 与"通用插件"诉求的边界 |
| **D7** | 防抖与判定参数 | 冻结滑动方向判定阈值（建议 30° 容差）、连翻防抖窗（建议 120 ms）、长按与多指排除规则 | 误触发率是否达标 |
| **D8** | 验收方式 | 作者自测 + **≥ 3 名试用者**各场景实测，产出可用性记录 | 是否可判定"通过" |

**出口**：本单全员确认后锁定；与已有眼动项目共用同一套"口径变更走评审"的纪律。

## 3. 量化指标红线

### 3.1 交互正确性

| 维度 | 指标 | 阈值 |
|---|---|---|
| 方向判定 | 四方向判定正确率 | ≥ 99.5% |
| 误触发 | 无操作状态下的误翻页率 | ≤ 1% |
| 连翻 | 快速连续翻页不丢事件 | ≥ 10 次/秒下无丢帧 |
| 边界 | 首 / 末页方向越界 | 不报错、不跳页 |

### 3.2 性能

| 维度 | 指标 | 阈值 |
|---|---|---|
| 响应 | 端到端延迟（D1 口径） | P95 ≤ 100 ms，目标 ≤ 50 ms |
| 加载 | 首屏可交互时间（4G） | ≤ 2 s |
| 体积 | 静态资源总大小（gzip） | ≤ 200 KB |
| 稳定性 | 连续使用 30 分钟 | 无内存持续增长、无明显卡顿 |
| 成本 | 托管费用 | **0 元**（免费额度内） |

### 3.3 可用性

| 维度 | 指标 | 阈值 |
|---|---|---|
| 上手 | 零说明理解操作 | ≤ 10 s |
| 首次成功 | 试用者首次操作即成功翻页 | ≥ 90% |
| 可访问性 | 键盘完整可达、焦点可见 | 100% 核心操作可键盘完成 |

### 3.4 隐私与安全（档位 0 特化）

| 维度 | 指标 | 阈值 |
|---|---|---|
| 数据出域 | 上传用户内容 / 行为数据 | **零上传** |
| 摄像头 | 首发申请摄像头权限 | **不申请**（档位 0 无眼动） |
| 第三方 | 引入追踪 / 广告脚本 | 不引入 |
| 隐私红线 | 若将来接入眼动：原始人脸帧 | 端侧处理，不出设备（继承已有项目红线） |

## 4. 明确不做（首发范围外）

| # | 不做项 | 原因 |
|---|---|---|
| 1 | 任何后端服务 / 账号体系 | 档位 0 决策 |
| 2 | 手机→大屏遥控 | 档位 1，因用户面未收敛而暂缓 |
| 3 | 眼动输入接入 | 依赖已有项目达 M1（W12），晚于首发 |
| 4 | 浏览器扩展形态 | D6 决策，延后到 v2 |
| 5 | 场景专属功能（演讲者视图 / 漫画连续滚动 / 无障碍专属热区） | 场景中立原则 |
| 6 | 八方向翻页 | D2 决策 |
| 7 | 接管任意第三方网站的原生滚动行为 | 属扩展领域，且兼容风险不可控 |

---

## 5. 验收方式

| 步骤 | 内容 | 产出 |
|---|---|---|
| 1 | 作者自测：按第 3 节全部指标实测并留档 | 自测记录表 |
| 2 | 试用测试：≥ 3 名试用者，覆盖桌面 / 移动各至少 1 人 | 可用性记录（含首次成功率、上手时间） |
| 3 | 兼容性测试：D5 各浏览器各跑一遍核心流程 | 兼容性矩阵 |
| 4 | 结论 | 《首发验收报告》：通过 / 有条件通过 / 不通过 |

---

## 6. 变更流程

1. 任何指标或决策门变更，需提交变更说明（原因 + 影响面）。
2. 变更经确认后方可执行，并在本单登记版本与日期。
3. 已冻结指标不得私自放宽；如需放宽必须在验收报告中显式标注。
