01整体架构：两条输入链路，一个防冲突闸门

摄像头同时喂两条链路。眼动负责"指哪"，手势负责"点哪 / 滚哪"，最后经防冲突闸门统一触发。

链路 A · 眼动（WebGazer 2.1.2）
摄像头→ WebGazer 视线坐标→ EMA 低通→ 按钮磁吸（gravity）→ 光标→ 驻留 800ms 点击
链路 B · 手势（MediaPipe Hands）
摄像头→ 21 点手部关键点→ 手势分类→ 状态机（3 帧确认 / 冷却）→ 动作键 / 方向滚动
汇合 · 防双触发闸门
链路 A+ 链路 B→ handBusyUntil：手势活跃时冻结 dwell→ 单次触发→ （可选）WebSocket 后端

手势：6 静态手势 + 方向滚动

已完成

目标：手不碰设备，比手势就能操作。

  • MediaPipe Hands 21 点关键点
  • ✊ 握拳=确认　👍 拇指=返回
  • ☝️ 食指=主页　✌️ 二指=菜单
  • 🖐 指尖朝上=上滚　指尖朝下=下滚
  • 状态机：3 帧确认 + 900ms 冷却 + 120ms 滚动节流
  • 滚动演示列表 + 图例 + 诊断行实时手势

判定方法
手指伸直：指尖到手腕距离 > 指根到手腕 × 倍数
拇指伸直：拇指尖到掌心 > 拇指根到掌心 × 倍数
滚动方向：四指指尖平均 y vs 掌心 y（±0.12 死区）

验收：1–2 米能稳识别握拳 / 食指 / 二指 / 张开；拇指中等。

5

最终形态：免接触操作

目标

目标：坐/站在电脑前 1–2 米，全程不碰鼠标键盘、不戴任何设备，用"看 + 手势"完成操作。

  • 眼睛看按钮 → 光标吸附 → 盯 0.8s 点击
  • 或比手势直接触发动作键
  • 手掌指尖朝上/下 → 内容滚动
  • （可选）WebSocket 把指令发给后端 / 外部应用

适用场景
• 双手被占用（做饭 / 维修 / 演示）
• 不便接触（医疗 / 洁净环境）
• 无障碍（行动不便者）

衡量：连续 10 次操作误触发 ≤ 1 次，无需回退到鼠标。

03最终理想效果（用户视角）

不谈技术，只描述"用起来是什么感觉"。

👀

看哪里，光标去哪里

视线扫过屏幕，光标会"被按钮吸住"，不会在按钮边缘来回抖。看准了，停 0.8 秒，自动点击。

✊

比个手势，就是一次指令

握拳 = 确认，拇指朝上 = 返回，食指 = 主页，二指 = 菜单。每个手势要"稳住 3 帧"才生效，避免误触。

🖐

手掌一翻，页面就滚

张开手掌、指尖朝上，内容往上滚；指尖朝下，内容往下滚。滚多快由手势停留时间决定。

🧘

全程零接触

1–2 米外坐着或站着，不用碰键盘鼠标，也不戴任何设备。手上有油、有水、在忙，都能操作。

05踩坑预警（绝对不要再踩）

这些都是已经踩过、付过代价的坑，写在这里是为了不让下一个人重犯。

1. 红外补光灯对 Brio 无效

Brio 是 RGB 传感器、带 IR-cut 滤镜，红外光会被滤掉，开红外补光灯画面不会变亮。要补光只能用可见光（白光 / LED）。

2. "张开手掌"不能同时做"返回"和"上滚"

张开手掌、指尖朝上，与"指尖向上=上滚"是同一个姿态，无法区分。所以「返回」改成了拇指朝上，张开手掌专门留给滚动。

3. 没有 node，改 JS 只能靠括号自检 + 浏览器实测

本项目无任何构建工具。改完 index.html 先跑 python3 .deepworks/tmp/check_js_balance.py 检查括号/字符串平衡，再到浏览器实跑。不要假设"改完就能用"。

4. 滚动不要加 scroll-behavior: smooth

它和手动 scrollTop 累加冲突，会导致滚动卡顿/回弹。已移除，不要再加回去。

5. 手势触发时眼动 dwell 会"补刀"

手势触发动作的瞬间，眼动光标可能正停在同一个按钮上，dwell 满 800ms 后又点一次。已用 handBusyUntil 冻结，不要删这段逻辑。

6. 双远程：必须 push origin，不是 jarvis

origin 是团队仓库（推送目标），jarvis 是个人 fork。裸 git push 会推到错误仓库，务必 git push origin main；被拒就 fetch + rebase，绝不 force。

7. 别把"合成眼动 / hero 模板"当成真实功能

已清理 gaze-pointer-lab.html（合成眼动驱动视觉折痕）和 creative-developer-hero.html（纯网页模板）。它们不接摄像头、不跑模型，看着像功能其实不是。

8. 标定覆盖层会挡住诊断行

右上角 dbg-line 的 z-index:60 被标定层（100）盖住，标定时看不到 gaze 帧数。需要时可提到 110（尚未改）。
